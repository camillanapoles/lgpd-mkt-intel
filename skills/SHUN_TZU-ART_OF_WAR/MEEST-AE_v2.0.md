## 3. MOTOR DE SELEÇÃO DINÂMICA DE FERRAMENTAS (DTS)

### 3.1 Princípio Fundamental

> NENHUMA ferramenta é aplicada por default. Cada ferramenta é selecionada via critérios derivados do contexto específico da dimensão Sun Tzu em análise.

```
DERIVAÇÃO > PRESCRIÇÃO

Antes (erro): "Use SWOT para análise interna"
Depois (v2.0): "Para esta dimensão, neste contexto, com estas incertezas,
                qual ferramenta DERIVA o maior valor informacional?"
```

### 3.2 Algoritmo de Seleção Dinâmica (DTS)

```
FUNÇÃO select_tools(dimensao_sun_tzu, contexto_cenario, incerteza_map):

  PASSO 1 [S]: Extrair necessidade informacional da dimensão
    necessidade = derive_information_need(
      dimensao=dimensao_sun_tzu,
      contexto=contexto_cenario,
      incerteza=incerteza_map
    )

  PASSO 2 [Q]: Filtrar ferramentas candidatas do catálogo
    candidatas = filter_catalog_by_need(necessidade)

  PASSO 3 [I]: Aplicar FDC-U às ferramentas candidatas
    PARA CADA ferramenta EM candidatas:
      scores[ferramenta] = score_tool(ferramenta, necessidade, contexto_cenario)

  PASSO 4: Selecionar top-N (N derivado, não fixo)
    N = derive_N(candidatas, contexto_cenario)
    selecionadas = top(scores, N)

  RETORNAR:
    dimensao: dimensao_sun_tzu
    necessidade_informacional: necessidade
    ferramentas_selecionadas: selecionadas
    ferramentas_rejeitadas: candidatas - selecionadas
    justificativa_dinamica: generate_selection_cot(scores)
```

### 3.3 Score de Ferramenta via FDC-U

```
Score_Ferramenta = Σ [ peso_i × f_i( dimensao_i ) ]

Dimensões de Avaliação (6 critérios mínimos):

1. ADEQUAÇÃO À NECESSIDADE (peso 0.30, f_i: +)
   "Quanto a ferramenta resolve a necessidade informacional específica"

2. CUSTO DE APLICAÇÃO (peso 0.20, f_i: -)
   "Tempo, dados, expertise necessários para aplicar"

3. COBERTURA DA INCERTEZA (peso 0.20, f_i: +)
   "Quanto a ferramenta reduz H(incerteza) do cenário"

4. TEMPORALIDADE (peso 0.15, f_i: +)
   "Recência da metodologia vs. validade no contexto atual"

5. INTEROPERABILIDADE (peso 0.10, f_i: +)
   "Facilidade de integrar output com outras ferramentas selecionadas"

6. REVERSIBILIDADE (peso 0.05, f_i: -)
   "Custo de desfazer a análise se o cenário mudar"

Threshold de seleção: Score >= 6.5 (derivado do contexto, não fixo)
```

## 4. SISTEMA "CARTAS NA MESA" (CNM)

### 4.1 Conceito Fundamental

> "Cartas na Mesa" é o mapa lógico REAL da situação. Cada entidade do cenário é uma carta. Cada carta é avaliada por critérios dinâmicos (mínimo 5). Se o critério muda, o valor da carta muda. Nenhuma carta é aceita sem avaliação cruzada.

```
ANTES (erro): "O mercado é bom" (afirmação vaga, não verificável)
DEPOIS (CNM): "Carta: Mercado Enterprise SaaS | Score: 7.2/10 |
               Critérios: [Crescimento 8.5] [Barreira 6.0] [Regulação 7.5]
               [Competição 5.5] [Timing 8.5] | Certeza: 82% (atualizado 2026-05)"
```

### 4.2 Estrutura de uma Carta

```yaml

  # CRITÉRIOS DINÂMICOS (mínimo 5, derivados do contexto)
  criterios:
```

### 4.3 Derivação de Critérios Dinâmicos

```
FUNÇÃO derive_criteria(carta, contexto_global):

  # Base: Critérios universais aplicáveis a qualquer carta
  base_criteria = [
    'relevancia_para_objetivo',
    'mensurabilidade',
    'temporalidade',
    'corroboracao_fontes',
    'impacto_estrategico'
  ]

  # Contexto-específico: Critérios que emergem do tipo de carta
  SE carta.tipo == 'DOMINIO':
    context_criteria = [
      'tamanho_de_mercado',
      'taxa_de_crescimento',
      'intensidade_competitiva',
      'barreiras_de_entrada',
      'regulamentacao'
    ]
  SE carta.tipo == 'DIMENSAO':
    context_criteria = [
      'alinhamento_com_estrategia_macro',
      'viabilidade_tatica',
      'custo_de_implementacao',
      'tempo_de_execucao',
      'risco_de_falha'
    ]
  SE carta.tipo == 'RISCO':
    context_criteria = [
      'probabilidade_de_ocorrencia',
      'impacto_financeiro',
      'impacto_reputacional',
      'capacidade_de_mitigacao',
      'velocidade_de_materializacao'
    ]
  SE carta.tipo == 'OPORTUNIDADE':
    context_criteria = [
      'potencial_de_retorno',
      'janela_temporal',
      'recursos_necessarios',
      'capacidade_de_execucao',
      'sustentabilidade_competitiva'
    ]
  SENÃO:
    context_criteria = infer_criteria_from_context(carta, contexto_global)

  # Combinar e garantir mínimo 5
  all_criteria = base_criteria + context_criteria
  ENQUANTO len(all_criteria) < 5:
    additional = derive_gap_criteria(carta, all_criteria)
    all_criteria.append(additional)

  # Atribuir pesos via AHP (Analytic Hierarchy Process)
  weights = calculate_ahp_weights(all_criteria)

  RETORNAR critérios com pesos e funções de impacto
```

## 5. CERTEZA ATUALIZADA E DECAY TEMPORAL

### 5.1 Princípio

> Cenários antigos são erro certo. A certeza de cada carta decai com o tempo. Uma carta não atualizada por 6+ meses em mercado volátil tem certeza < 50% — ou seja, é mais arriscado confiar nela do que lançar uma moeda.

### 5.2 Fórmula de Decay Temporal

```
Certeza_atualizada(Carta, t) = Certeza_base × Decay(t) × Corroboração(t)

Onde:
  Decay(t) = 1 / (1 + λ × Δt)
    λ = taxa de decay (depende da volatilidade do domínio)
      λ = 0.05 -> Domínio estável (ex: infraestrutura pública)
      λ = 0.15 -> Domínio moderado (ex: manufatura)
      λ = 0.30 -> Domínio volátil (ex: SaaS, cripto, AI)
      λ = 0.50 -> Domínio caótico (ex: startup pré-PMF)
    Δt = tempo desde última atualização (em meses)

  Corroboração(t) = 1 + α × (novas_fontes_corroborativas - fontes_contraditórias)
    α = 0.1 (peso da nova evidência)
```

### 5.3 Regras de Atualização Obrigatória

```yaml
regras_atualizacao:
  - condicao: "Domínio volátil (λ >= 0.30) E Δt > 1 mês"
    acao: "REAVALIAÇÃO OBRIGATÓRIA de todas as cartas do domínio"
    severidade: CRITICAL

  - condicao: "Certeza_atualizada < 60%"
    acao: "FLAG: Carta não confiável para decisão estratégica"
    severidade: WARNING

  - condicao: "Certeza_atualizada < 40%"
    acao: "REMOVER carta do tabuleiro até revalidação"
    severidade: ERROR

  - condicao: "Nova fonte contraditória detectada"
    acao: "RECALCULAR corroboração e reavaliar score"
    severidade: HIGH

  - condicao: "Evento de mercado material (M&A, regulamentação, disrupção)"
    acao: "REAVALIAÇÃO TOTAL do tabuleiro"
    severidade: CRITICAL
```

### 5.4 Exemplo de Decay em Ação

```markdown
## EXEMPLO: Decay Temporal — Carta D01 (Mercado Enterprise SaaS)

### Estado Original (2026-01-09)
- Certeza_base: 92%
- λ: 0.30 (SaaS = volátil)
- Fontes: Gartner Q4 2025, IDC 2025

### Estado após 4 meses sem atualização (2026-05-09)
- Decay(4) = 1 / (1 + 0.30 × 4) = 1 / 2.2 = 0.455
- Certeza_atualizada = 92% × 0.455 = 41.8%
- STATUS: CARTA REMOVIDA DO TABULEIRO (abaixo de 40%)

### Ação corretiva:
1. Buscar novos dados: Gartner Q1 2026, IDC 2026
2. Reaplicar ferramentas: PESTEL atualizado, Porter 5 Forces revisado
3. Recalcular scores com novos critérios se contexto mudou
4. Reintegrar carta ao tabuleiro com certeza atualizada

### Estado após atualização (2026-05-09)
- Novas fontes: Gartner Q1 2026, IDC 2026
- Certeza_base: 86% (ligeira queda devido a sinais de saturação)
- Decay(0) = 1.0
- Certeza_atualizada = 86% × 1.0 = 86%
- STATUS: CARTA REINTEGRADA
```
