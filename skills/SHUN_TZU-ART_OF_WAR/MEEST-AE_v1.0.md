## 1. CONSTITUIÇÃO E MANDATO FUNDACIONAL

### 1.1 Princípios Invioláveis

```
P1. ENSINAR_A_PESCAR: O output não é um plano pronto — é o método para gerar planos estratégicos impecáveis em qualquer contexto empresarial.
P2. HOLISMO_ESTRATÉGICO: Nenhuma análise tática é válida sem alinhamento com a estratégia macro; nenhuma estratégia macro é válida sem viabilidade tática.
P3. DECOMPOSIÇÃO_DINÂMICA: Critérios de avaliação são derivados (não enumerados) via FDC-U, adaptando-se ao contexto específico do cenário de negócio.

P7. CONTEXTO_COMO_ATIVO: Engenharia de contexto (CE) é tratada como ativo estratégico, não como overhead.
```

3. **DIVISÃO ATÔMICA**: Fragmentar cada fator em elementos não-redutíveis.

4. **DEFINIÇÃO OPERACIONAL**: Cada termo chave definido mensuravelmente.

### [Q] QUESTIONADOR: VALIDAÇÃO EPITEMOLÓGICA DO CENÁRIO

**Objetivo**: Aplicar o 5N Sistêmico + Classificação de Evidência à análise estratégica.

**Procedimento:**

1. **5N Aplicado à Estratégia**:
   - **Negação**: O que foi omitido na análise de mercado? (cegos spots)
   - **Nuance**: Graus de liberdade na execução? (cenários alternativos)
   - **Núcleo**: O que é irrefutável? (dados brutos, não interpretações)
   - **Nexo**: Como cada fator Sun Tzu conecta com domínios adjacentes? (financeiro, legal, tecnológico)
   - **Nulidade**: O que falsificaria esta estratégia? (hipótese de invalidação)

2. **Classificação de Evidência**:
   - `FACT`: Dado de mercado verificável (relatório regulatório, 10-K, IBGE)
   - `INFERENCE`: Conclusão lógica a partir de facts (ex: "competidor X está vulnerável porque margem caiu 40%")
   - `SPECULATION`: Indução com confiança <90% (ex: "mercado vai crescer 20% no próximo ano")
   - `BELIEF`: Não-fundamentado → FLAG `[UNVERIFIED]`

3. **Questionamento Recursivo (3× Por quê?)**:
   - Aplicado a cada conclusão intermediária da análise estratégica.

**Output [Q]**:
```yaml
TRACE-Q:
  classificacao_epistemologica: [FACT|INFERENCE|SPECULATION|BELIEF por afirmação]
  falacias_potenciais: [lista de viés detectados]
  questoes_criticas_abertas: [o que ainda não se sabe]
  hipoteses_falsificacao: [o que invalidaria o plano]
```

### [I] INOVADOR: SÍNTESE ESTRATÉGICA VIA FDC-U + DTP

**Objetivo**: Gerar o plano estratégico através de decomposição de critérios universais e orquestração topológica de decisões.

#### 3.3.1 FDC-U Aplicado às 13 Dimensões Sun Tzu

**Fórmula de Utilidade Agregada:**
```
Score_Estratégico(Cenário) = Σ [ w_i × f_i( A_i(Cenário) ) ]

Onde:
  w_i  = peso da dimensão i (Σw_i = 1.0)
  f_i  = função de transformação FDC-U (+ direta / - inversa / ~ ótima / > limiar)
  A_i  = atributo mensurável do cenário na dimensão Sun Tzu i
```

**Taxonomia de Funções de Impacto (FDC-U) aplicada:**

| Tipo | Símbolo | Quando Usar (Contexto Sun Tzu) | Fórmula |
|------|---------|-------------------------------|---------|
| Positivo | (+) | Mais é melhor (ex: market share, NPS, LTV) | f(x) = x |
| Negativo | (-) | Menos é melhor (ex: CAC, churn, desperdício) | f(x) = 10 − x |
| Ótimo | (~) | Existe valor ideal (ex: timing de lançamento, fase de mercado) | f(x) = 10 − \|x − m\| |
| Limiar | (>) | Mínimo aceitável (ex: runway de caixa, compliance) | f(x) = 0 se x < t |
| Logaritmico | (log) | Retornos decrescentes (ex: investimento em marketing) | f(x) = log(x+1) |

#### 3.3.3 DTP — Orquestração das Decisões Estratégicas

**Fase 0**: Enumeração de candidatos (estratégias/táticas possíveis)
**Fase 1**: DAG de dependências ("estratégia X depende de Y estar pronto")
**Fase 2**: Matriz de Impacto (FDC-U acima)
**Fase 3**: Ordenação topológica ponderada
**Fase 4**: Dispatch
   - CRIAÇÃO → MODUS OPERANDI (novas iniciativas)
   - CORREÇÃO → CHECK-MATE (fix de processos)
   - REFATORAÇÃO → CHECK-MATE + MODUS OPERANDI
**Fase 5**: Re-avaliação contínua (cada execução altera o campo de jogo)

### [A] ADVERSARIAL: STRESS-TEST ESTRATÉGICO

**Objetivo**: Destruição construtiva do plano — Advocatus Diaboli aplicado à estratégia de negócios.

**Procedimento:**

1. **ADVOCATUS DIABOLI**:
   - "Qual o melhor argumento CONTRA esta estratégia?"
   - "Sob quais condições esta estratégia falha CATASTROFICAMENTE?"
   - "Qual viés cognitivo me fez chegar a esta conclusão específica?"
   - "O que Sun Tzu diria contra este plano?" (Cap. VIII — As Nove Variações)

2. **Stress Test Estratégico**:
   - **Edge Case**: Mercado encolhe 50% em 90 dias
   - **Worst Case**: Concorrente principal lança produto idêntico com preço 30% menor
   - **Dados Contraditórios**: Indicador-chave de mercado inverte tendência

3. **Checklist de Viés Cognitivo** (obrigatório):
   - [ ] Viés de confirmação (busquei apenas dados pró-estratégia?)
   - [ ] Viés de âncora (dependi do primeiro dado de mercado recebido?)
   - [ ] Viés de recência (sobrepus notícia de ontem sobre dados históricos?)
   - [ ] Viés de autoridade (aceitei relatório de consultoria sem validar metodologia?)
   - [ ] Viés de ação (preferi "atacar" sem justificativa Sun Tzu clara?)

4. **Falsificação Popperiana**:
   - Identificar UMA observação empírica que invalidaria a estratégia.
   - Se impossível de falsificar → REJEITAR como metafísico/não-científico.

5. **Antifragility Score (SAE v4.0)**:
   ```
   AFS = (Opcionalidade × Redundância × Feedback_Loop) / Fragilidade
   ```
   - AFS > 3.0: Robusto → APROVADO
   - AFS > 5.0: Antifrágil → OURO
   - AFS < 1.5: Frágil → REJEITADO

**Output [A]**:
```yaml
TRACE-A:
  contra_argumentos: [lista robusta]
  condicoes_falha_catastrofica: [cenários de ruptura]
  vieses_detectados: [lista + mitigações]
  teste_falsificacao: [observação que invalidaria]
  antifragility_score: [X.XX]
  status: [APROVADO|REJEITADO|CONDICIONAL]
```
